# Skill: security-review

## Purpose
مراجعة أمنية منهجية لأي Feature قبل اعتبارها Done، بافتراض دور مهاجم متمرس.

## When to Use
قبل إغلاق أي Task تلمس: المصادقة، الدفع (Stripe/شام كاش)، إدخال بيانات من المستخدم، أو أي Endpoint جديد بالـ API.

## Inputs
- الكود المعني (Endpoint/Serializer/View)
- `docs/api/API.md` للسياق

## Preconditions
الكود مكتمل وظيفياً ويمر باختباراته الأساسية.

## Steps
1. افترض أنك مهاجم متمرس — كيف يمكن استغلال هذا الكود؟
2. تحقق: هل كل مدخل من العميل يمر بـ Validation صريح؟
3. تحقق: هل أي عملية دفع/طلب تُؤكَّد فقط عبر Webhook موقَّع، لا عبر الواجهة؟
4. تحقق: هل توجد Secrets أو بيانات حساسة مكشوفة بالكود أو الاستجابة؟
5. تحقق: هل Rate Limiting مفعّل على المسارات الحساسة (login, register, payments)؟
6. تحقق: هل رسائل الخطأ تكشف تفاصيل داخلية (Stack Trace، أسماء جداول)؟

## Rules
- لا يُعتبر Feature Done دون اجتياز هذه الخطوات كاملة عند لمسها لأي من النقاط الحساسة أعلاه.
- أي ثغرة مكتشفة تُوثَّق فوراً مع: الثغرة، طريقة الاستغلال، الأثر، الاحتمالية، الإصلاح المقترح.

## Validation
لا توجد ثغرة حرجة (Critical/High) مفتوحة قبل الدمج بالفرع الرئيسي.

## Expected Output
تقرير مراجعة أمنية مختصر (نجاح كامل، أو قائمة ثغرات مع إصلاحات مطلوبة) مرفق بالـ Pull Request.
