# IDEA-VALIDATION.md — Ware

## المشكلة
المنتجات الصناعية والتجارية السورية تفتقر لمنصة عرض وبيع إلكتروني موحّدة بمستوى تجربة مستخدم احترافي، مع دعم فعلي لوسائل الدفع المحلية. المشترون حالياً يعتمدون على قنوات مبعثرة (صفحات تواصل اجتماعي، اتصال مباشر) دون تجربة شراء إلكترونية منظمة وموثوقة.

## المستخدم المستهدف
- مشترون أفراد أو جهات صغيرة يبحثون عن منتجات صناعية/تجارية سورية
- مدير المنصة (Admin) الذي يدير الكتالوج والطلبات كاملاً (نموذج Single-Vendor)

## الحاجة الحقيقية
- ثقة بوسيلة الدفع (خصوصاً المحلية — شام كاش)
- سهولة تصفح وبحث عن منتجات مصنّفة بوضوح
- تجربة شراء كاملة من التصفح حتى تأكيد الطلب دون احتكاك

## الحل المقترح
منصة PWA واحدة، بائع واحد يدير الكتالوج، تدعم Stripe وشام كاش، بتصميم وتجربة استخدام مستوحاة من نجاح منصات عربية رائدة (سلة) من ناحية الفلسفة العامة للتجربة، مع بنية قابلة لإعادة الاستخدام كقالب لمنصات مستقبلية (Cosmetic Lady، Brand).

## البدائل التي تم النظر فيها
- **الاعتماد على منصات جاهزة عالمية (Shopify) أو عربية (سلة نفسها):** مرفوض لأنه لا يوفر تكامل شام كاش أصلاً، ولا يمنح ملكية كاملة للمنصة والبيانات لبناء عائلة منصات لاحقاً.
- **بناء نواة Multi-Tenant مشتركة لكل المنصات الثلاث من البداية:** مرفوض (قرار مستخدم مباشر) لصالح مشاريع مستقلة أبسط وأكثر عزلاً.

## القيمة المقترحة
تجربة شراء إلكترونية محلية موثوقة، بدعم دفع سوري حقيقي، وتصميم يضاهي أفضل المنصات الإقليمية.

## المخاطر
- عدم اكتمال بحث تكامل شام كاش قد يؤخر مرحلة API Design (راجع RESEARCH.md — بحث 002)
- غياب بيانات منافسين سوريين مباشرين يجعل تقدير حجم الفرصة التجارية غير مكتمل حالياً
- فصل Nuxt عن Django كـ API يزيد تعقيد المصادقة وإدارة الجلسات مقارنة بحل موحّد

## الافتراضات (Assumptions)
- المستخدم المستهدف يفضّل تجربة ويب PWA على تطبيق موبايل Native في هذه المرحلة
- شام كاش يوفر آلية تكامل برمجي (API/Webhook) يمكن الاعتماد عليها — **يحتاج تأكيداً فعلياً**
- حجم الكتالوج في البداية يسمح بنموذج Single-Vendor دون الحاجة لتعقيد Multi-Vendor
