## Design System — الهوية البصرية المعتمدة

| الدور | اللون | Hex | الاستخدام |
|---|---|---|---|
| Primary | أزرق داكن | `#0C447C` | الهيدر، أزرار التنقل، الروابط، عناصر الثقة |
| Accent / CTA | كهرماني | `#BA7517` | أزرار الشراء والدفع، العناصر التي تحتاج انتباهاً فورياً |
| Neutral (نص) | رمادي غامق | `#2C2C2A` | النصوص الأساسية والعناوين |
| Background | رمادي فاتح دافئ | `#F1EFE8` | خلفية الصفحة، بطاقات المنتجات |
| Success | أخضر | `#3B6D11` | تأكيد الطلب، نجاح الدفع، توفر المنتج |
| Danger | أحمر (يُحدَّد لاحقاً بنفس منطق الرامب) | — | فشل الدفع، أخطاء النماذج، نفاد المخزون |
| Warning | كهرماني فاتح | — | تنبيهات (مخزون منخفض، مهلة الجلسة) |

**قاعدة إعادة الاستخدام لعائلة المنصات:** نفس بنية الأدوار (Primary/Accent/Neutral/Background/Success/Danger/Warning) تُستخدم حرفياً لـ Cosmetic Lady وBrand، ويتغيّر فقط قيم Primary وAccent (Hex) حسب هوية كل منصة — بلا أي تغيير هيكلي بالمكونات أو الـ CSS classes.

### الخطوط
- **العربية:** خط Cairo أو Tajawal (وضوح عالٍ بالعربية، يدعم الأوزان المتعددة)
- **قياسات:** H1: 28px / H2: 22px / H3: 18px / Body: 16px / Caption: 13px

### المكونات الأساسية (Design System / UI Kit)
- Button (Primary / Secondary / Ghost / Danger)
- Product Card (صورة، اسم، سعر، زر إضافة سريع للسلة)
- Input / Select / Textarea مع حالات Validation مرئية
- Badge (متوفر / غير متوفر / خصم)
- Toast/Notification (نجاح، خطأ، تنبيه)
- Modal (تأكيد، تفاصيل سريعة)
- Skeleton Loader (بدل Spinner فقط عند التحميل الأولي للقوائم)

## منهجية التصميم
Design Thinking مختصر: تعاطف مع مشتري يبحث عن منتج صناعي بسرعة وثقة → تحديد المشكلة (تجربة شراء عربية موثوقة بدفع محلي) → توليد أفكار الواجهة → Wireframes منخفضة الدقة → Mockup عالي الدقة بالهوية أعلاه → اختبار مع مستخدمين حقيقيين بعد أول نسخة قابلة للاستخدام.

## الشاشات الأساسية (Screens)
1. الصفحة الرئيسية (منتجات مميزة، تصنيفات، بحث)
2. صفحة قائمة المنتجات (فلترة + بحث)
3. صفحة تفاصيل منتج
4. السلة
5. Checkout (عنوان الشحن → مراجعة → اختيار وسيلة الدفع)
6. صفحة تأكيد الطلب
7. حساب المستخدم (تسجيل/دخول، الطلبات السابقة)
8. لوحة الإدارة (Django Admin — خارج نطاق Wireframes الخاصة بالمتجر، تصميمها جاهز عبر django-unfold)

## التنقل (Navigation)
هيدر ثابت (Sticky) يحوي: الشعار، البحث، أيقونة السلة (بعداد)، حساب المستخدم. تنقل سفلي (Bottom Navigation) على الموبايل يتماشى مع نمط PWA (الرئيسية، التصنيفات، السلة، الحساب).

## Wireframes / Mockups / Prototype
- **Wireframe:** رسم منخفض الدقة للشاشات الثمانية أعلاه (يُنفَّذ بأداة تصميم خارجية مثل Figma قبل بدء الترميز الفعلي — خارج نطاق ملفات الكود)
- **Mockup:** تطبيق الهوية البصرية أعلاه على الـ Wireframes
- **Prototype:** نموذج تفاعلي بسيط لتدفق Checkout تحديداً (الأكثر حساسية) قبل الترميز الكامل

> ملاحظة: ملفات Figma الفعلية تُدار خارج هذا المستودع؛ هذا الملف يوثّق القرارات والمواصفات فقط.

## حالات الواجهة (States)
- **Loading:** Skeleton Loader لبطاقات المنتجات، Spinner فقط لأزرار الإجراءات (مثل "جارٍ الدفع")
- **Empty:** رسالة ودّية + إجراء مقترح (مثال: سلة فارغة → زر "تصفح المنتجات")
- **Error:** رسالة بلغة بشرية واضحة، بدون أي Stack Trace، مع إجراء لإعادة المحاولة عند الإمكان

## الإتاحة (Accessibility)
- معيار WCAG 2.1 Level AA كحد أدنى
- نسبة تباين ألوان ≥ 4.5:1 (تم اختيار الألوان أعلاه مع مراعاة هذا القيد على النصوص الأساسية)
- alt text لكل صور المنتجات
- أزرار اللمس ≥ 44px

## Responsive
Mobile First إلزامي (أغلبية المستخدمين المتوقعين عبر الهاتف). نقاط الاختبار: 320px / 768px / 1440px.

## تعدد اللغات / RTL
العربية هي اللغة الأساسية بواجهة RTL كاملة من الإطلاق الأول. دعم الإنجليزية (LTR) مؤجل لفئة Could في SCOPE.md — النصوص تُفصَل عن الكود من اليوم الأول (i18n جاهز بنيوياً) لتسهيل الإضافة لاحقاً دون إعادة هيكلة.
